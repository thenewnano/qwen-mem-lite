### P1-1 数据目录经符号链接到达时，打印的"复制命令"不复制，只造了一个指向原目录的链接

- 说法：
  - `CHANGELOG.md:21-22` "On damaged pages doctor and `fts-check rebuild` fail with what they found and a command that copies the data directory"
  - `README.md:964` "On damaged pages it writes nothing and prints a command that copies the data directory first."；`README.zh-CN.md:739` 同义
  - `lib/db-unusable.mjs:145` 的建议文本 "copy the data directory before anything writes to it again"，`lib/db-unusable.mjs:148` 起的 docblock "The copy of the data directory that PAGE_DAMAGE_COPY_ADVICE asks for"
- 实际：命令是 `test ! -e <dir>.copy-<日期> && cp -a <dir> <dir>.copy-<日期>`。`cp -a` 含 `-P`，命令行上的符号链接不跟随；`resolveDataDir` 不做 realpath。数据目录（默认 `~/.claude-mem-lite`，或 `CLAUDE_MEM_DIR`）是一个指向别的盘的符号链接时（常见的搬家做法），命令退出 0，"副本"是一个指向**同一个活目录**的新符号链接，一个字节都没复制；之后任何写入同时改了"副本"。用户照提示做完会以为手里有一份副本。
- 证据：`scripts/symlinkcopy.mjs`（`out/probes/symlinkcopy.txt`）：`~/.claude-mem-lite -> …/bigdisk/cml-data`，store 为 VACUUM 过、freelist 列着活叶子的库，新树 `cli.mjs doctor` 打印
  `✗ Database integrity: the database's pages are damaged, so nothing was rebuilt` 和
  `test ! -e …/home/.claude-mem-lite.copy-2026-10-25 && cp -a …/home/.claude-mem-lite …/home/.claude-mem-lite.copy-2026-10-25`；
  运行它 → `exit 0 | the "copy" is a SYMLINK -> …/tmp/symlink/bigdisk/cml-data`；`ls -la` 显示两个都是 `lrwxrwxrwx … -> …/bigdisk/cml-data`。
  对照：真实目录时同一命令确实复制（`out/probes/faces.txt`，exit 0，出现 `my data.copy-2026-10-25` 目录；第二次运行被 `test ! -e` 拦下 exit 1）。
- 适用人群：数据目录路径本身是符号链接的用户。实际目录的用户不受影响。
