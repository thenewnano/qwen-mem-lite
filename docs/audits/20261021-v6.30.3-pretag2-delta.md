### Close-order probe
Setup: a healthy WAL store, an old session holding 200 committed rows in an 869 KB WAL, the exact remedy command, then a new session writing 50 rows. Each session closes the way the server shuts down: `wal_checkpoint(TRUNCATE)`, then close.

| Mode | Old closes before the new session opens | Old closes last | Old closes while the new session is open |
|---|---|---|---|
| rm-only | nothing lost | new session's 50 lost | old session's 200 lost |
| restore | snapshot-only row gone (restore overwritten) | new session's 50 lost, restore overwritten | old session's 200 lost |
| set-aside | old's 200 in `.corrupt` | old's 205 in `.corrupt` | old's 200 in `.corrupt` |

In every cell where the store survives, integrity_check is ok. The CHANGELOG sentence ("can lose its recent writes, or write them over the restored file") is therefore TRUE.
