through such runs with its per-character loop and searched natively only once every 32 steps. The
cache does not help when each depth reads its own line once per pass. Output is identical on every
shape below (25/25 timing shapes, same sha1).

## NOT CHECKED
- SQLITE_IOERR during quick_check: no fault-injecting file system was used.
- SQLITE_BUSY thrown by quick_check itself in the window between the sqlite_master probe and the
  PRAGMA. That would print `✗ Database: database is locked` where base printed `⚠ … in use`. Not
  reproduced; a lock held for the whole run gives the same ✗ on both trees.

  CORRUPT into a row, and connect errors arrive as SQLITE_ERROR or SQLITE_CORRUPT; not reproduced.

  row before the table and vtab passes; not reproduced. The PRAGMA's prepare connects FTS5 tables,
