## Findings

### F-1 (P3) The ten-minute sweep does nothing when the data dir is a symlink
scripts/setup.sh:167 `find "$DB_DIR" -maxdepth 1 -name '.legacy-backup-setup-*' -mmin +10 -exec rm -f {} + ...`
GNU find's default -P does not follow a starting point that is a symlink, so with ~/.claude-mem-lite (or CLAUDE_MEM_DIR)
being a symlink to a directory the sweep examines only the link itself and never removes a private file. The guard's
glob two lines up (`"$DB_DIR"/claude-mem-lite.db.legacy-backup-*`) does follow the link, and so did the r1 bash-glob
sweep this replaced. Leftovers are partial or whole copies of the claude-mem store (and its log), one per killed or
failed session start; on a symlinked data dir they stay forever. Body claim "It now removes its own private files not
written for ten minutes" is false for that population. Fix: `find "$DB_DIR/" ...` or `find -H "$DB_DIR" ...`.
Repro:
  SB=.../scratch/sb-symlink; mkdir -p $SB/home $SB/elsewhere/data; ln -sfn $SB/elsewhere/data $SB/home/.claude-mem-lite
  : > $SB/elsewhere/data/claude-mem-lite.db; printf partial > $SB/elsewhere/data/.legacy-backup-setup-1234-1600000000
  touch -d @1600000000 $SB/elsewhere/data/.legacy-backup-setup-1234-1600000000; run-setup.sh $SB
  -> exit=0; `-rw-r--r-- ... Sep 13 2020 .legacy-backup-setup-1234-1600000000` still there
  control (same file, real dir) -> "(removed)". Direct: `find <link> -maxdepth 1 -name ... -mmin +10` -> nothing;
  `find <real> ...` -> the file.

### F-2 (P3) install's killed-copy leftovers are now never removed once a store exists; two comments say install removes them
scripts/setup.sh:157-158 "install's own (`.legacy-backup-copy-`) are install's to remove, under its lock."
tests/setup-sh-legacy-db-relocation.test.mjs:240 "(it does, under its lock)".
install.mjs:197 returns `skip` when claude-mem-lite.db exists, before the EXDEV branch's sweep at :209. A store is
created at the first session start (hook.mjs session-start, parallel to setup.sh), so after an install killed during
its cross-filesystem copy, the next install skips and nothing ever removes `.legacy-backup-copy-<pid>-<ms>[-wal|-shm]`
(up to a full copy of the claude-mem store). At 0d896e3a setup.sh's pid sweep removed them; 1f684eca removed that path.
(Not present in v6.30.7, which had no cross-fs copy.) The commit body itself corrects 0eae0593 to "only while no store
is in place", but the new setup.sh comment does not carry that qualifier.
Repro (scratch/sb-installleak, data dir on /dev/shm): plant `.legacy-backup-copy-<deadpid>-1600000000000{,-wal}` aged
2 h + claude-mem-lite.db; `node install-plain.mjs <old> <new>` -> {"action":"skip"}; HEAD setup.sh -> both leftovers
still listed; 0d896e3a setup.sh -> both gone.

### F-3 (P3) "not written for ten minutes => no running copy" fails on wall-clock jumps; a live copy's file is removed and an orphan log is left
scripts/setup.sh:156-157 "a session start is killed at 30 s, so none of them belongs to a running copy."
The 30 s cap is a monotonic timer in the host; mtime and find's -mmin are wall clock. A live copy's private file reads
>10 min old after a suspend/resume or forward clock step during the copy, when setup.sh runs outside the hook (install.mjs:3719
tells users to "run setup.sh"), or (reasoned, not run) when the data dir's FS stamps mtime with a lagging server clock (NFS/SMB).
The log copy is not rewritten while the database copies, so it is the exposed file. Outcome in every case: the live copy's
next mv fails, so no incomplete backup database is placed (contract holds); but if the live copy had already placed its
log, `claude-mem-lite.db.legacy-backup-<s>-wal` is orphaned and nothing ever removes it (setup sweeps only
`.legacy-backup-setup-*`, install only `.legacy-backup-copy-*`, the guards ignore a log alone). Also: a private file with a
future mtime (clock set back) is kept until the clock passes it (GNU find: `-mmin +10` matched ages 601..721 s, not 590 s
or -600/-86400 s).
Repro (scratch/sb-clock): A's mv wrapper pauses 3 s before placing its database; during the pause A's private db is
`touch -d '-11 minutes'`; B runs. Output: B exit=0 "backed up to ...-1792931532"; A exit=0 "⚠ Legacy DB backup failed";
final dir: `...-1792931531-wal` (orphan), `...-1792931532`, `...-1792931532-wal`.
The same orphan log is left by a kill between the two mv's (the existing 'between placing the log and the database' case
leaves it; the test does not assert on it).

### F-4 (P3) Regression vs v6.30.7: overlapping session starts now make two full backups

Each duplicate is a full copy of the claude-mem store + log. No incomplete backup.

v6.30.7 (git show v6.30.7:scripts/setup.sh) -> `...-1792931420` only (B exit=0, skipped).
