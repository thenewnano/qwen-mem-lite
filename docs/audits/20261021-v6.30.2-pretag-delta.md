## Findings

### P3-1: The title and one D#479 sentence say more than the code does (CHANGELOG.md:5, :23-24; df45f934 subject)
The title says "a hook of yours under a `claude-mem-lite…` directory is no longer deleted". Line 23-24 says
"a hook of yours under `~/.claude-mem-lite/` no longer sets it off". This holds only where that directory
carries no claude-mem-lite package.json. A direct install puts one there:
- INSTALL_DIR = ~/.claude-mem-lite (install.mjs:35, :66).
- source-files.mjs:376 copies package.json there.
- Then isProductRoot makes any `<root>/scripts/<x>` or `<root>/hook.mjs` path "ours" (lib/hook-prune.mjs:112).

Probe (sandbox HOME; fmt.js present) with isMemHookCommand, old → new:

| home dir | command | old | new |
|---|---|---|---|
| ~/.claude-mem-lite has no package.json | `node ~/claude-mem-lite-notes/scripts/fmt.js` | true | false |
| ~/.claude-mem-lite has no package.json | `node ~/.claude-mem-lite/scripts/fmt.js` | true | false |
| ~/.claude-mem-lite/package.json names claude-mem-lite | `node ~/.claude-mem-lite/scripts/fmt.js` | true | **true** |

So for a direct-install user, which is the audience of the setup.sh warning, a hook of theirs at
~/.claude-mem-lite/scripts/<x> still sets off the warning. install, uninstall and cleanup-hooks still
delete it. Line 21-23 states the product-root rule. The title and line 23-24 drop it. Few users are
affected, and the behaviour is consistent across the faces, hence P3.
