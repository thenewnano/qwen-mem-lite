## Q2 Model identity

Per the API reference there is no dated id and no separate alias for Haiku 5.5:
`claude-haiku-5-5` on the Claude API, Foundry, Vertex and Claude Platform on AWS;
`anthropic.claude-haiku-5-5` on Bedrock. Traces (stubbed fetch):
- Gateway deployment name (`ANTHROPIC_BASE_URL` + `ANTHROPIC_DEFAULT_HAIKU_MODEL=my-haiku-55-deployment`):
  body `{"model":"my-haiku-55-deployment","max_tokens":1000,"temperature":0}`. If the 400 text
  names the backticked field and says deprecated/unsupported (retry regex haiku-client.mjs:651),
  `_temperatureDeprecated` caches it and the retry goes out WITHOUT temperature but also without
  `thinking:disabled` and without the schema -> adaptive thinking on the 300-2000 token budgets
  (the failure the A/B measured on OpenRouter: 8/18 rerank cut off). If the text does not match,
  every call is a 400 followed by the CLI fallback, uncached, for the life of the process.
  The real Haiku 5.5 400 text is not documented in the reference and was not observed here.
- Bedrock-form id via a gateway (`anthropic.claude-haiku-5-5`): same old body (`"temperature":0`).
- OpenRouter variants: `OPENROUTER_MODEL=anthropic/claude-haiku-5.5:nitro` / `:floor` -> body
  `{"model":"anthropic/claude-haiku-5.5:nitro","max_tokens":1000,"temperature":0}`: no
  reasoning-off, no response_format. Exact `anthropic/claude-haiku-5.5` gets the strict body for
  EVERY tier (the override covers sonnet calls too), which is correct since the model is 5.5.
CHANGELOG states this ("A model ID you set yourself that is not claude-haiku-5-5 /
anthropic/claude-haiku-5.5 gets the same request as before") and the contract lists gateways as
a non-goal, so this is P3-2, not P2.

`{"variants":["a","b`, `{"ranked":[3,1,5`, and for truncations with a balanced inner object;
rerank.extractRanked returns null for `{"ranked":[3,1,5` and `[3, 1, 5`. So "partial JSON as
success" does not happen at the parsers; the cost is a null with no fallback.

## Findings

### P3-1 test gap: the refusal case cannot say NO to "refusal -> null"
tests/haiku-client.test.mjs:2041. The stub answers `content: []`, so without the refusal
branch's `return null` (mutation H5) the empty content still yields null and the CLI answer;
174/174 stay green. The behaviour the branch exists for, a refusal that carries partial text,
is untested (the probe shows the code handles it). Fix: stub
`content:[{type:'text',text:'{"title":"half'}]` with `stop_reason:'refusal'` and assert the CLI
answer comes back.

### P3-2 strict body misses Haiku 5.5 under any other name
haiku-client.mjs:77, 167, 577, 1090 (exact `Set.has`). OpenRouter `:nitro`/`:floor` slugs, the
Bedrock form `anthropic.claude-haiku-5-5` behind a gateway, and gateway deployment names get the
old body: `temperature:0`, thinking on, no schema (traces in Q2). Depending on the 400 text this
is either one 400 per process then thinking-on calls without the schema, or a 400 + CLI
fallback on every call. Documented in CHANGELOG and outside the contract, but the CHANGELOG's
own gateway advice ("Set ANTHROPIC_DEFAULT_HAIKU_MODEL to the model or deployment the gateway
routes to") leads a Foundry user with a renamed 5.5 deployment onto this body. Fix: normalise
before the lookup (strip an OpenRouter `:variant` suffix, a leading `anthropic.` /
`<region>.anthropic.` prefix), and give deployment names an explicit opt-in (env flag) rather
than guessing; or say in the CHANGELOG that a renamed 5.5 deployment is not supported yet.

### P3-3 truncation never reaches the CLI fallback (pre-existing, not introduced by the range)
haiku-client.mjs:667-678 (no `stop_reason:"max_tokens"` check), :1112-1114 (no `finish_reason`
check), :522 (`if (primary?.text) return parseJsonFromLLM(...)`). A truncated primary counts as
success: JSON dispatchers return null without trying the CLI; text dispatchers return the cut
text (`{"variants":["a","b` from callHaiku; `[3, 1, 5` from callLLMWithModelAsync). Parsers
reject it, so it is a lost call, not bad data. Exposure on the default ids is low now that
thinking/reasoning is off; it is the mode a P3-2 id hits. Fix: treat `max_tokens` / `length`
as a failed primary (null) so the fallback runs.

### P3-4 OpenRouter leg has no refusal handling
haiku-client.mjs:1112-1114. Contract: "A refusal must yield null with a log line". On
OpenRouter, null content -> null + CLI fallback, logged only as the generic "openrouter call
failed" in callHaiku/callLLMWithModel(Async) and not at all in callModelJSONAsync; partial
content with `finish_reason:"content_filter"` is returned as success (probe). Uncertain because
OpenRouter's actual refusal shape for Anthropic models was not observed (no live calls). Fix:
null + debugLog on `finish_reason` content_filter, `native_finish_reason` refusal, or a
`message.refusal` field.

### P3-5 text-by-content takes an empty text block
haiku-client.mjs:675-677. `find((b) => typeof b?.text === 'string')` returns `''` from
`[{type:'text',text:''},{type:'text',text:'{"a":"x"}'}]`, so the call falls to the CLI and the
real answer is dropped (probe). Unlikely shape without tools/citations. Fix: join every
`type === 'text'` block's text.

### P3-6 doc: three async dispatchers' JSDoc omit jsonSchema
haiku-client.mjs:358, 438, 494 (`@param {{timeout?,maxTokens?,temperature?}} [opts]`), while
callHaiku/callLLMWithModel document it.

### P3-7 test gap: the episode prompt text is unpinned
tests/hook-llm.test.mjs:325 compares the handler's prompt with `buildEpisodePrompt(episode)`
itself, so it guards the wiring (L3 red) but not neutrality; L1 (`Error: yes`->`YES`) leaves
262/262 green across hook-llm, audit-r10-installer-global-writes, episode-input-filter,
feature-sweep-hooks, llm-episode-narrative-preserve-r3 and scope-label tests. Neutrality of this
release holds by the textual diff in Q5. Fix: one golden string per branch (single entry,
several entries).

### P3-8 test gaps in tests/benchmark-haiku-model-ab.test.mjs (repo-only)
:104-124. B1: restoring with `env[k] = undefined` instead of `delete` passes because `toEqual`
ignores undefined-valued keys; on process.env that assignment writes the string "undefined".
B2: a slug arm that stops setting CLAUDE_CODE_PATH passes because `base()` already holds
MISSING_CLI (main() also sets it, so the run itself stays blocked). Fix: `toStrictEqual`, and
start `base()` without CLAUDE_CODE_PATH.

### P3-9 benchmark/episode-flush-replay.mjs:198 workerFields is an unguarded twin of hook.mjs:786-806
Identical today (window 65536 / 32768, same extractDiagnosis options, scrubbed desc,
inputTags, diag, diagOut). Nothing fails if hook.mjs changes and the twin does not, and the
A/B population would then stop matching production silently. Repo-only. Fix: extract the
shared lines into a helper both call, or a sync test.
