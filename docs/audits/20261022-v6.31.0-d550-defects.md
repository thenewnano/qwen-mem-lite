# D#550 blind defect review — commit 1b23dcc2 (`git diff main...1b23dcc2`)

## Verdict

Not ready as written. Two P0s (both reproduced): (1) on a store with a damaged page, the product's own
`delete --confirm` leaves a 0-byte `*.pre-delete-*.bak`. doctor's new remedy names that 0-byte file as
"the newest backup snapshot", and the README's snapshot block, run with that path, empties the store:
0 of 3,019 observations left. (2) If the DB **file** is a symlink, the README's `.recover` procedure
prints `ok`, leaves out every row in the log (50/350), and the placed store is then "database disk image
is malformed". Five P1s: the README procedure deletes exactly the rows doctor's new CHECK check flags
(3/3, and 2/2 for NOT NULL), prints `ok`, and puts them in no `lost_and_found`; a hang on an adversarial
CHECK text; and a false ✗ on sound stores that hold a user-made virtual table or a user index that needs a
sqlite3-CLI collation. In the branch's favour: the integrity check itself never changed a byte of a store
or its log in any run, and the README numbers I re-measured match the archive (75/286 stops on the 869 set).

  type name ending in `CHECK(…)` triggers it. Script: A.8.

### A.3 dmg-leaf.cjs (bytes into one leaf page of a table)

```javascript
// node dmg-leaf.cjs <db> <table> <frac> <offset> <hexbytes>: overwrite bytes in one leaf page of <table> (main file).
const D = require('/home/ai/dev/claude-mem-lite/node_modules/better-sqlite3');
const fs = require('fs');
const [p, table, frac, off, hex] = process.argv.slice(2);
const d0 = new D(p, { readonly: true });
const pages = d0.prepare(`SELECT pageno FROM dbstat WHERE name=? AND pagetype='leaf' ORDER BY pageno`).pluck().all(table);
d0.close();
const pg = pages[Math.floor(pages.length * Number(frac))];
const fd = fs.openSync(p, 'r+');
fs.writeSync(fd, Buffer.from(hex, 'hex'), 0, hex.length / 2, (pg - 1) * 4096 + Number(off));
fs.closeSync(fd);
console.error(`damaged ${table} leaf page ${pg} (${pages.length} leaves) at +${off}`);
```
