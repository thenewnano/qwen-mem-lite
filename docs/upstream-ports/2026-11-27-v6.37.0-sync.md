## Approach

A single merge of `upstream/main` into `main`, same as the four earlier passes.
33 files conflicted. The dominant collision was the fork's dual-layout steering
model against upstream's rewrite of the path-based steering API (D#509(4),
D#880, `lib/regular-file.mjs`, `lib/project-link.mjs`): upstream moved every
instruction-file read to a bounded regular-file reader and every write to a
link-refusing assertion, while the fork writes two layouts (`.claude`/`QWEN.md`
and `.claude`/`CLAUDE.md`). `claudemd.mjs` was reconstructed so upstream's
path-based `readBlockAt` / `writeBlockAt` / `removeBlockAt` stay the only
implementations and the fork's layout loop wraps them. Elsewhere, files whose
only fork change was the rebrand took upstream's logic and re-applied the fork
identity; files with fork logic (the OpenAI-compatible LLM leg, install/update
identity, the data-dir detail doc name) kept the fork and folded upstream's new
behaviour in by hand.

The second collision was the new upstream tests. They were written against
upstream's identity (`claude-mem-lite`, `CLAUDE_MEM_*`, `~/.claude-mem-lite`,
`plugin_claude_mem_lite.md` beside a project) and were rebranded to the fork's
data dir, DB, env prefix and project doc names. Three fixtures needed a macOS
adaptation: `/proc/self/fd` is Linux-only, a separate `.GIT` fixture cannot
exist on APFS beside `.git`, and the developer's global git excludes hides
`.claude/settings.local.json` unless the test neutralises it.

## Fork deviations introduced

- `claudemd.mjs`: rebuilt around upstream's path-based functions. `docRel` /
  `stateRel` / `managedTargets` / `assertWritable` take a layout; `readBlock`,
  `writeManaged` and `removeManaged` loop the two layouts and merge their
  outcomes; `isOwnAdoptionArtifact` checks `.claude` and `.qwen` names;
  `writeManagedIn` checks all three layout targets before writing anything.
  `steeringDetailDocPath()` now reads `QWEN_MEM_DIR` (it arrived reading
  `CLAUDE_MEM_DIR`) while keeping the legacy `plugin_claude_mem_lite.md` name.
- `haiku-client.mjs`: upstream's `cliSpawnEnv()` helper added once, with the
  fork's `QWEN_MEM_HOOK_RUNNING` variable, and used by both spawn legs;
  upstream's `windowsHide: true` kept.
- Env rebrand in new upstream code: `QWEN_MEM_NO_TEMPLATE_REFRESH`,
  `QWEN_MEM_PRETOOL_PATH_PRECISION`, `QWEN_MEM_PRETOOL_RECENCY_FIRST`,
  `QWEN_MEM_EDGE_DECAY`, `QWEN_MEM_ERROR_RECALL_REPEAT_MIN`,
  `QWEN_MEM_ERROR_RECALL_GIT_RECORD`.
- `install.mjs`: the purge store pattern recognises `qwen-mem-lite.db` (plus the
  legacy `claude-mem-lite.db` and `claude-mem.db` names), and its messages name
